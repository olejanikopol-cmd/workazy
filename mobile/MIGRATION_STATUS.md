### Domain / data decisions

- Mirrored only the web `PlanTask` shape (`id, title, completed, date, createdAt?,
  updatedAt?`) into `src/types/plan.ts`. No `Assignment.description/dueDate`, no
  persisted numbers, no `position`. Assignment/Goal CRUD is deferred.
- One ordered `tasks` array across all dates in key `workazy-native-plan-v1`
  (envelope `{ version: 1, tasks, savedAt }`; the key is distinct from the web
  storage key and the web snapshot is never imported).
- Rows filtered per day without re-sorting; numbering `String(index + 1).padStart(2,'0')`
  derived per selected day. IDs (`task-${Crypto.randomUUID()}` via `expo-crypto`) are
  keys and mutation targets; duplicate titles allowed.
- Complete/uncomplete changes only `completed` + `updatedAt`; editing changes only
  `title` + `updatedAt`; move swaps adjacent same-day rows in the full array and
  touches both `updatedAt`s; boundary moves are no-ops. Explicit uncheck persists —
  the web "completed first" merge is not ported.
- New/edited titles: trim outer whitespace, 1–300 chars (server `parseTaskItem`
  limit), internal newlines preserved; multiline input creates ONE item; a stored
  over-300 title still loads intact.
- Dates use device-local calendar semantics (`localDateIso` / `getPlanDates` in
  `planDates.ts`): calendar getters/`setDate`, never `toISOString().slice`, never
  `+86400000`. Relative mode (`today`/`tomorrow`) default today, kept for the
  mounted workspace, refreshed on foreground and at local midnight; captured editor
  date is fixed when the add sheet opens; editing keeps the item's original date/ID.
- Storage is the only source of truth. Hydration gate; no mount autosave, no writes
  before hydration; `load()` coalesces; persist-before-commit with a synchronous
  write lock (second mutation returns `busy`); write failure keeps last committed
  state, exposes the error, unlocks, and allows retry. Malformed/unknown snapshots
  and read failures go to load-error with raw bytes preserved and a Retry action.
- The pure store (`planStore.ts`) takes injected `storage`/`now`/`createId`; only
  `usePlanStore.ts` imports AsyncStorage and Expo Crypto.

Fixes applied after the Codex review of the Slice 2 pass:

1. **Plans selector always visible + day state preserved across segments.**
   `PlansScreen` now renders the План / Задания / Цели segmented control above the
   content in every segment (including План), and owns the relative Today/Tomorrow
   hook (`usePlanDay`) itself, passing it into `PlanDayView`. Switching segments no

   План → Задания → План. `PlanDayView` consumes the day via a `day` prop

   the relative date is computed through a new pure `dateForMode()` helper.
2. **No lost edits during save / stale save completions.**
   `PlanItemSheet` now has a synchronous local `busy` lock (started in the same
   frame as the save tap, in addition to the store `saving` flag): the multiline
   input is `editable={false}`, and close/cancel/delete/toggle/move/save are
   disabled while busy; handlers also early-return on `busyRef`. Save success
   closes through a new identity-guarded `onSaveComplete` prop: `PlanDayView` only
   closes the sheet whose key is still the open one (`closeSheetIfSame`), so an
   old sheet's late completion cannot close a newly opened sheet. A draft revision
   captured at save start (`isDraftUnchanged`) additionally prevents a completion
   from closing if the draft somehow changed mid-write. Read-mode delete uses the
   same guarded completion.
3. **Date refresh lifecycle.**
   `usePlanDay` refreshes on screen focus (`useFocusEffect`) and app foreground
   (`AppState` active), and runs a bounded periodic recheck (`setInterval` 60s;
   the stable `refresh` makes no-op ticks free) so device clock/timezone/midnight
   changes cannot leave Today/Tomorrow stale. Removed the single midnight
   setTimeout (which could be the only refresh source).
4. **Strict timestamp validation.**
   `isValidIsoTimestamp` no longer relies on `Date.parse` normalization: it
   regex-matches the full ISO form and round-trip-verifies every calendar/time
   field with an explicit real `Date`, rejecting impossible dates such as
   `2026-02-30T12:00:00.000Z` (and non-leap `2026-02-29`, `04-31`, `24:00`, `:60:`
   etc.). `parseSnapshot` uses it for `savedAt` and optional timestamps, so such a
   stored value now yields a load-error instead of silently normalizing.
5. **Persistence + regression coverage.**
   Added a real fresh-store round trip: store A mutates and persists bytes; a
   brand-new store B hydrating those exact bytes restores tasks/order/completion/
   dates/optional timestamps exactly, and mutating B does not touch A's snapshot.
   Added `tests/plan-sheet-guard.test.mjs` covering the identity/draft-revision
   guards, plus strict-timestamp and `dateForMode` cases. Existing tests were not
   weakened.

### Slice 2 blocker fix — UTC `Z` timestamp validation (2026-09-10)

**Problem (Codex review):** `isValidIsoTimestamp` validated `Z`-suffixed
timestamps with **local-time** `Date` construction and local getters. Under
`TZ=Europe/Kyiv`, the valid UTC instant `2026-03-29T03:30:00.000Z` falls inside
the spring-forward DST gap (03:00 → 04:00 local): local construction normalizes
it to 04:30, so the validator returned `false`. A snapshot containing that
timestamp could be written, but a fresh store loading the persisted bytes
entered `load-error`.

**Fix (`mobile/src/features/plans/planDates.ts`):** `Z` is now treated strictly
as UTC. The validator keeps the exact ISO shape regex, then uses a pure-UTC
parse + **exact `toISOString()` round-trip** (`new Date(Date.parse(value))
.toISOString() === value`) — no local-time construction/getters for `Z`
timestamps. This:
- accepts valid UTC instants inside any local DST gap (Kyiv spring-forward,
  LA fall-back) in every timezone;
- still rejects impossible calendar dates (`2026-02-30T12:00:00.000Z`
  normalizes to `2026-03-02T…` → mismatch → `false`);
- preserves genuine leap days (`2024-02-29T12:00:00.000Z` → `true`);
- keeps rejecting malformed/out-of-range forms (`24:00`, `:60:`, `2026-13-45`,
  missing `.000Z`, etc.) via the shape regex + `Date.parse` NaN.

Snapshot validation is unchanged in strictness — `parseSnapshot` still rejects
the whole envelope on any invalid `savedAt`/optional timestamp.

**Regression coverage added:**
- `tests/plan-dates.test.mjs`: `isValidIsoTimestamp` accepts
  `2026-03-29T03:30:00.000Z` / `2026-03-29T04:30:00.000Z` (Kyiv gap) and
  `2026-11-01T01:30:00.000Z` / `2026-11-01T08:30:00.000Z` (LA fall-back);
  existing impossible-date/leap/out-of-range assertions retained.
- `tests/plan-store.test.mjs`: store A (clock = `2026-03-29T03:30:00.000Z`)
  persists a task; a fresh store B hydrating the exact persisted bytes loads
  `ready` (not `load-error`), with `savedAt`/`createdAt`/`updatedAt` equal to
  the DST-gap timestamp and zero writes during hydration.

### Slice 3 Codex review fixes — 2026-09-11 (final guarantees)

1. **CRUD → immediate coordinated reconciliation.** Every add/edit/delete commits
   durably, then requests an immediate coordinated reconciliation of the LATEST
   committed state which is awaited by the Sheet's save path, so a process exit
   right after CRUD leaves event and notification state as consistent as the
   operation that completed. Timer/foreground passes remain a safety net only.
2. **One coordinator, no stale races.** A single-flight queue
   (`calendarReconcileCoordinator.runCoordinatedReconcile` +
   `useCalendarLifecycle.calendarRequestReconcile`) re-reads the store snapshot at
   the start of each pass. `shouldAbort` stops OS mutation as soon as a newer
   event mutation commits (store `revision` counter), and the coordinator re-runs
   with the fresh state. A deleted event can never keep/regain a notification in
   the converged state.
3. **Persistence failures are surfaced.** `persistRegistry` throws when the
   envelope (events + registry) write fails; the pass reports `status: 'error'`;
   no OS request is scheduled for an ID whose registry pre-write failed; the next
   pass recovers. Tombstones are dropped only after confirmed OS absence.
4. **DST production behavior.** The planner derives explicit instants with
   `zonedDateTimeToUtcEarlier`: Europe/Kyiv fall-back `2026-10-25 03:30` →
   `2026-10-25T00:30:00.000Z` (earlier occurrence); a spring-forward gap such as
   `2026-03-29 03:30` produces NO request, and the editor refuses to save such a
   time (visible validation message) instead of keeping misleading reminder
   state.
5. **Content-aware verification.** Existing owned OS requests are only treated as
   up-to-date when ownership metadata AND kind AND content (title/body) AND the
   decoded trigger instant all match (`pendingMatchesRequest`); a mismatch
   cancels and re-schedules. The adapter decodes every shape the installed SDK
   actually returns (`decodeTriggerEpochMs`): JS `{ type:'date', date }`, native
   `{ type:'date', timestamp }` and — for our one-shot date alerts on iOS —
   `{ type:'timeInterval', seconds, repeats }`. The timeInterval shape has no
   absolute instant by itself, so the adapter records the schedule context
   (`data.scheduledAt`) at schedule time; the decoded instant is compared with a
   ±2 s tolerance so an unchanged reminder verifies instead of being
   cancelled/rescheduled forever.
6. **Capacity.** Obsolete/changed/out-of-window owned requests are cancelled
   BEFORE scheduling; capacity is recomputed from the CURRENT OS inventory after
   cancellation; the 48-request app cap is preserved; valid later reminders are
   never permanently starved and are refilled on later passes when eligibility
   changes (added refill-by-time test).
7. **Clock safety.** A fresh clock is consulted immediately before each schedule
   decision; triggers that became past during the pass are skipped, never
   scheduled as immediate alerts. Clock/timezone changes converge on the next
   pass (timezone is read live each pass).
8. **Sheet correctness.** Editing keeps the stored reminder exactly (an event
   with no reminder is not silently converted to 30 minutes); dirty detection
   covers title/note/date/time/Без-времени/reminder; synchronous busy guard
   disables pickers and close/cancel/save/delete while a save is pending; only a
   completion for the same sheet identity/revision may close a newer instance;
   the view follows the saved event's destination date.
9. **Calendar refresh/navigation.** The today marker updates on focus/foreground/
   periodic (single source, never stale); month arrows select day 1 of the
   destination month; edited events moved to another date reveal that date.

### Slice 3 review fixes — round 2, 2026-09-11 (final guarantees)

11. **iOS scheduled-trigger decoding fixed.** The installed SDK reads our
    one-shot date alerts back as `{ type: 'timeInterval', seconds, repeats }`
    (iOS stores a non-repeating date alert as a `UNTimeIntervalNotificationTrigger`),
    which previously decoded to `null` and caused endless cancel/reschedule churn.
    `decodeTriggerEpochMs(trigger, scheduledAt)` now decodes it using the

    reconciliation) is pending, close/cancel/edit/save/delete/pickers are all
    disabled and the modal cannot be dismissed. The parent applies every
    completion through `applySheetCompletion(current, completedKey, date)` reading

    opens → A's completion leaves B open.

    Regression test: time advances during the persist await → the expired trigger
    is not scheduled, the still-future one is.
14. **Capacity enforced before read-back.** A successful `os.schedule` consumes
    the slot immediately; a failing inventory read-back afterwards can no longer
    free it. Regression test: with cap = 1, schedule succeeds but verification

### Slice 3 review fixes — round 3, 2026-09-11 (final guarantees)

17. **Permission-state race fixed.** `refreshPermission`/`requestPermission` no
    longer spread a captured state before awaiting the permission call: they
    await first, then merge the permission result into the LATEST state. A
    delayed permission response can therefore never erase a newer scheduling
    error, a newer DST-gap warning, or a newer cleared warning. Regression tests
    cover BOTH directions (delayed read keeps a newer error + warning; delayed
    read does not resurrect a cleared warning) plus the prompt path.
18. **iOS timeInterval churn fixed principled.** Verification no longer compares
    the re-derived native instant against a fixed tolerance: the adapter persists
    the EXACT target instant inside the scheduled request
    (`data.targetTriggerAt`) and the decoded shape family is compared
    shape-scoped. (Round 4 tightens this further: the OS trigger is now REQUIRED
    to be decodable, and the handoff budget applies only to the iOS `interval`
    family — absolute/date/calendar shapes are strict.) Regression tests:
    simulated handoff latency (unit + end-to-end via the fake OS) verifies without
    churn, 1 h drift and a wrong persisted target are rejected.
19. **Post-schedule read-back uses the full matcher.** After `os.schedule` the
    pass no longer accepts a matching identifier alone: the returned pending
    request must satisfy the SAME matcher as existing notifications (identifier,
    ownership metadata, title/body, kind/eventId, trigger time). A read-back with
    the expected ID but wrong content or a wrong trigger fails verification while
    the already-consumed capacity slot is kept. Regression tests: correct request
    passes; wrong content fails; trigger 1 h late fails; wrong persisted target
    fails; cap = 1 with a failed read-back never schedules a second request.
20. **Production-path coverage.** The lifecycle policy is extracted into the pure
    `calendarNotificationController` (shared state, single-flight reconcile
    queue, race-safe permission merging, focus/foreground/periodic policy,

    binding over it, so the tested logic is exactly the logic production runs.
    New tests drive the controller with the REAL store, reconciler and fake OS:
    calendar focus → today refresh + reconciliation; AppState gating (background/
    inactive periodic tick does no work, `active` ticks immediately); permission
    races; and the editor's synchronous busy lock (shared by save and delete) is
    exercised via the production `createSheetLock`, including "an old save/delete
    completion cannot close a newer editor".
21. **Years 0000-0099 no longer remapped.** `calendarDates.ts` (and the shared

### Slice 3 review fixes — round 4, 2026-09-11 (final guarantees)

22. **Trigger verification requires a verifiable OS trigger.** The adapter reports
    the decoded trigger family (`absolute` / `interval` / `unknown`) and

### Domain / data decisions (Slice 4)

1. **Mirror, don't merge.** `src/types/journal.ts` mirrors `JournalEntry`,
   `JournalMedia`, `JournalMediaKind`, `TranscriptionStatus`; `src/types/idea.ts`
   mirrors `Idea`, `IdeaCategory`, `IdeaStatus` with provenance comments and no

   `{ version: 1, ideas, savedAt }`. No generic merged Record model.
2. **Text protection over transport caps.** Journal bodies have NO application
   cap (the web editor has none; only the POST/PATCH/state APIs cap at 5,000).
   Long local entries are preserved (tested at ≥100,000 characters) and the
   README/status documents that >5,000-character entries are not currently
   backend-write compatible. Title (optional, ≤300 on change), mood (≤60 on
   change) and tags (≤20 tokens × ≤40 chars) are input rules with visible errors;

3. **Trim exactly like the web save.** New/changed title and body are
   outer-trimmed; every internal newline, blank line, emoji, combining sequence
   and internal space is preserved byte-for-byte. Snapshot parsing is structural:
   legacy longer text, unknown moods, empty strings and legacy long tag arrays are
   loaded and preserved without rewriting; only changed fields are re-validated.
4. **Media: metadata only, never fabricated.** Full `JournalMedia` metadata
   schema is validated (types/enums, finite non-negative `sizeBytes`, positive
   optional duration/dimensions, canonical timestamps, unique IDs, association to
   the parent entry) and preserved exactly through text edits and failed deletes.
   Byte-bearing attachment properties (Blob/File/ArrayBuffer/typed arrays/base64/
   data-URL/file or temporary-playback URI fields) are rejected explicitly, while
   prose/transcripts that merely resemble a data URL stay valid. No media buttons,
   no players, no upload/transcription/R2/D1 wiring, no camera/mic permissions.

   thought/new; stored order preserved (new prepend; edit/status change keeps
   position); both filters are UI-only with «Все» and AND semantics; `plan` never
   creates a PlanTask/Goal. Timestamps are required and strictly canonical UTC
   (not the web Ideas `todayIso()` date-only metadata).
6. **Native-safe async policy (shared under `src/features/records/`).** One
   synchronous sheet lock per editor covers save AND delete before any await with
   `finally` release; the store keeps its own synchronous write gate; completion
   is applied only to the CURRENT sheet identity captured synchronously at open,
   so an old async completion can never close/redirect/clear a newer editor.
   Dirty-close protection covers every field; deletion confirms natively.

   survive switching; the Records route keeps a single list-level scroll owner
   (no outer ScrollView around FlatLists). Restart defaults to Journal/New entry.
8. **Deferred to Slice 5+ (not stubbed):** recording, camera/mic permissions,
   upload, transcription, playback, R2/D1, sync/auth, export/import, Records
   reminders, Finance, Goals.
